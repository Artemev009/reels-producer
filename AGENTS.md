# Правила работы над проектом

Для каждой задачи используем один и тот же обязательный цикл:

1. Изменяем код в локальном репозитории на компьютере пользователя.
2. Проверяем изменённую версию локально.
3. Коммитим проверенные изменения в Git.
4. Отправляем коммит в ветку `main` репозитория GitHub.
5. Render автоматически разворачивает новый Docker-образ из `main`.
6. Проверяем опубликованную версию по внешнему адресу Render.

Задача не считается завершённой, пока локальная версия, GitHub и опубликованная версия не соответствуют одному коммиту либо явно не описан внешний блокер.

Не редактировать рабочие файлы непосредственно на сервере. Источник истины — файлы локального репозитория и ветка `main` на GitHub.
